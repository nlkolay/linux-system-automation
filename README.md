# Linux System Automation & Infrastructure Telemetry ⚙️

Набор сервисных сценариев на языках Bash и Python для оркестрации локального узла, мониторинга аппаратного состояния накопителей и автоматического управления жизненным циклом данных (Data Lifecycle Management).

Решения ориентированы на эксплуатацию в средах виртуализации на базе гипервизора Proxmox Virtual Environment и серверных операционных систем Debian GNU/Linux.

---

## Архитектурные задачи комплекса

1. **Безопасная утилизация и ротация данных:** автоматический аудит библиотек через программные интерфейсы приложений, исключающий случайное удаление избранного или непросмотренного контента.
2. **Защита физических накопителей от перегрева и деградации:** стресс-тестирование и миграция данных с непрерывным аппаратным контролем температуры и состояния секторов.
3. **Аппаратная наблюдаемость (Observability):** потоковая передача метрик хоста в брокер очередей сообщений без использования тяжеловесных сторонних агентов.

---

## Структура проекта

### 1. Агент управления жизненным циклом данных (`agents/data_retention_agent.py`)
Асинхронный демон, контролирующий занятость дискового пространства и выполняющий управляемое удаление устаревших данных.

* **Принцип безопасного отказа (Fail-Safe):** при недоступности внешних программных интерфейсов, сетевых таймаутах или получении поврежденного ответа удаление принудительно блокируется.
* **Строгая валидация идентификаторов:** проверка уникальных идентификаторов The Movie Database исключает ложные срабатывания при частичном совпадении имен.
* **Учет прав пользователей:** удаление выполняется только в том случае, если медиафайл просмотрен всеми зарегистрированными пользователями и не добавлен в избранное ни одним из них.
* **Защита метаданными:** игнорирование каталогов с сервисным тегом коллекций.

### 2. Агент аппаратной телеметрии хоста (`telemetry/pve_mqtt_telemetry.sh`)
Легковесный фоновый скрипт командного интерпретатора Bash для хоста гипервизора.

* Считывает показатели температуры контроллеров накопителей из встроенного микрокода S.M.A.R.T. посредством утилиты `smartctl`.
* Рассчитывает процент использования объединенного пула накопителей и оперативной памяти.
* Передает телеметрию в брокер очередей сообщений по протоколу MQTT с использованием формата автоматического обнаружения Home Assistant MQTT Discovery.

### 3. Защищенный контроллер миграции данных (`storage/safe_disk_sync.sh`)
Оболочка над утилитой `rsync` для перемещения терабайтных массивов между изношенными накопителями.

* В реальном времени считывает температурные датчики и значения переназначаемых секторов (`Current_Pending_Sector`).
* При превышении порога нагрева или обнаружении сбойных секторов отправляет сигнал принудительного прерывания процесса, предотвращая термическое заклинивание привода головок.

## Развертывание и настройка

### Предварительные требования
На хосте и в средах исполнения требуются следующие пакеты:
```bash
    apt update && apt install -y smartmontools mosquitto-clients rsync python3 python3-requests
```
### Настройка агента ротации данных

1. Скопируйте шаблон конфигурации:
```
    cp config/retention_config.example.json /opt/automation/config.json
```

2. Укажите действительные сетевые адреса и ключи доступа к программным интерфейсам.

3. Установите системные службы:
```
    cp systemd/data-retention.* /etc/systemd/system/
    systemctl daemon-reload
    systemctl enable --now data-retention.timer
```

### Настройка телеметрии хоста

1. Разместите скрипт телеметрии:
```
    cp telemetry/pve_mqtt_telemetry.sh /usr/local/bin/
    chmod +x /usr/local/bin/pve_mqtt_telemetry.sh
```
2. Активируйте службу управления:
```
    cp systemd/pve-mqtt-telemetry.service /etc/systemd/system/
    systemctl daemon-reload
    systemctl enable --now pve-mqtt-telemetry.service
```
